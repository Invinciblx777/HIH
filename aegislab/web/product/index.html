Track 04 · Securing adversarial AI safety testing infrastructure

The secure range for AI red-teaming.

Guards protect the model. Attack tools test the model. AegisLab protects the test itself: red, blue and the model run in sandboxes that cannot reach each other, a broker hides which layer refused and when, and every result is sealed, released by a reviewer, and provable afterwards.

Launch live labVerify the evidence Source (MIT)

The live lab runs on your own Linux machine with rootless Podman. The hosted copy at aegislab-demo.onrender.com is read-only by design.

The problem: the red-team range leaks

Attack packs leak

If blue can read the attacks before the run, the score measures memory, not defence.

Refusals leak

If a reply arrives faster when the guard refuses, red learns which layer stopped it, and tunes the next attack.

Results leak early

If anyone can read results before a reviewer releases them, findings escape before they are fixed.

Logs can be rewritten

If the record can be edited afterwards, nobody outside the team can trust the evaluation.

How it works, in three steps

  1. 1

    Freeze

    The attack pack and the defence config are frozen; their sha256 enter a hash-chained audit log.

  2. 2

    Attack in sandboxes

    Red, blue (regex + AegisGuard model) and the model each run in a rootless Podman sandbox with no network. Only the broker passes messages, and every reply leaves at one fixed deadline with one refusal text.

  3. 3

    Seal, release, verify

    The run is sealed with Ed25519 checkpoints. A reviewer releases it. Anyone can verify the bundle offline; optionally its terminal checkpoint is anchored on Base.

Architecture

Outside-In: web agents meet the open web

TinyFish web agents did ordinary tasks (summarise an article, extract pricing, follow a support article) on synthetic pages that each hide one instruction: hidden div, HTML comment, white text, off-screen, alt text, footer, fake system block, link lure, base64 in a hidden div, aria-label with a fake reference code. What the agents brought back enters AegisLab as an untrusted attack pack and goes through the same broker, regex + AegisGuard model and sandboxed model. Agents also audited the hosted demo read-only, and every case became a signed n8n incident.

Small samples from one night of runs; agent behaviour can change. Details and limits: docs/integrations/TINYFISH.md.

Compliance mapping: evidence, not certification

AegisLab produces test evidence that can support these controls. It does not make a system compliant. Only what the code does is listed.

Hand clients sealed, verifiable results instead of screenshots.

Keep robustness test evidence for audits (EU AI Act Art. 15, NIST AI RMF).
